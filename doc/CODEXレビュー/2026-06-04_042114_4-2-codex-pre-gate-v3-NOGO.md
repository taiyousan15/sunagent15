## MUST-fix（実装前・Opus 全て ACCEPT・実検証済み）
1. **verified_update() を set-e 非依存で fail-closed 化**：`if verified_update` 経由だと関数内で errexit 無効。`mktemp`/tag解決/両 `curl`/sha照合/`mkdir`/`tar`/`rsync`/`cp`/`mv`/cleanup の**全 fallible コマンドに明示 `|| return 1`**、末尾に明示 `return 0`。
   - 検証: Bash Reference Manual — `if` 条件・関数呼出しの compound command 配下では errexit 無視。**ACCEPT**。
2. **cwd 処理**：既存 `cd "$REPO_DIR"` は **update.sh:47（legacy ブロック内）**＝verified 時にスキップされ、後続 root npm/build(L139/148) が誤 cwd（or 削除済 temp）で走る。→ 更新選択ブロック後・`NEW_VERSION`(L127)前に**無条件 `cd "$REPO_DIR"`** を追加（or `npm --prefix "$REPO_DIR"` 統一）。関数内 cp fallback の `cd "$TMP/x"` は**subshell 化**（`( cd "$TMP/x" && cp ... "$REPO_DIR/" ) || return 1`）で cwd leak 防止。
   - 検証: `grep -n 'cd "$REPO_DIR"' scripts/update.sh` → 47 のみ（legacy 内）。**ACCEPT**。
3. **verified モードで root build も fail-closed**：update.sh:148 は `2>/dev/null` で warn-continue（fail-open）。verified 時は root `npm run build` 失敗で exit1（legacy の warn-continue は温存）。
   - 検証: `grep -n 'npm run build --if-present' scripts/update.sh` → 148（warn-continue）。**ACCEPT**。
