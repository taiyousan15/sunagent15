## Findings — only NEW findings (HIGH / MED / LOW) introduced by 0f2f61d, OR remaining unaddressed 1st-round findings. For each: cite file:line, describe issue, impact, suggested fix.

### HIGH-1 (remaining from 1st-round HIGH-3)

File: `src/memory/MemoryService.ts:934`, `src/memory/MemoryService.ts:936`, `src/memory/MemoryService.ts:937`, `src/memory/MemoryService.ts:982`, `src/memory/MemoryService.ts:985`

Issue: The public `saveAgentStats(stats)` path now acquires `withAgentLock`, but it does not invalidate cache, re-read the current on-disk stats, perform an optimistic version check, or merge with the current state. It simply writes the caller-provided object through `saveAgentStatsLocked(stats)`. That textually addresses "unlocked" but does not resolve the cited lost-update bug for public read-modify-save users.

Evidence: A local repro with two `MemoryService` instances did:

1. `a.recordTask('race-agent', t1)`
2. `const stale = a.loadAgentStats('race-agent')`
3. `b.recordTask('race-agent', t2)`
4. `a.saveAgentStats(stale)`

Final `loadAgentStats('race-agent')` returned `totalTasks: 1` and `recentIds: ['t1']`; task `t2` was lost even though both write paths used the lock.

Impact: `recordTask()` and `cleanupOldTasks()` are now safe, but the exported public API can still erase a concurrent `recordTask()` update when a caller saves a stale `AgentStats` object. This is the same data-loss class as 1st-round HIGH-3 and is release-blocking under the binary release-quality standard.

Suggested fix: Do not expose raw stale-object saves as the safe public write API. Make `saveAgentStatsLocked` private-only and replace public writes with a locked mutation API such as `mutateAgentStats(agentName, fn)` that deletes cache, loads current stats inside the lock, applies the callback, then saves. If `saveAgentStats(stats)` must remain public, add an optimistic stale check inside the lock, e.g. re-read current stats and reject when `current.lastUpdated !== stats.lastUpdated` unless an explicit force mode is used. Add a regression test reproducing the four-step sequence above.
