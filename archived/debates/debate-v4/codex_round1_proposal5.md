## Risks of scripts/lib/setup-common.sh
- Relative path resolution: `source scripts/lib/setup-common.sh` is cwd-dependent and can break documented usage where `setup-project.sh` is invoked from another project directory ([scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:8), [scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:27)). Safe resolution must anchor to script file location, not `pwd`.
- `BASH_SOURCE` vs `pwd`: both shell scripts currently derive roots via `$0`/`dirname` ([scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:16), [scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:19)). A sourced library must use its own `BASH_SOURCE` path or explicit arguments; otherwise it can resolve wrong repo paths.
- PATH dependencies: shared blocks rely on external commands (`node`, `ln`, `cp`, `readlink`, `git`). `install.sh` checks tools earlier under `set -e` ([scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:14), [scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:145)), but `setup-project.sh` is `set +e` ([scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:14)); shared function behavior can diverge unexpectedly by caller.
- Environment variable leakage: current shared-name globals (`TARGET_SKILLS`, `TARGET_AGENTS`, `SETTINGS_FILE`) are set in both scripts ([scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:280), [scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:331), [scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:429); [scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:147), [scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:166), [scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:185)). A sourced file that assigns them can accidentally alter downstream logic.
- Cross-shell concerns: scripts are Bash-targeted (`#!/bin/bash`) and use Bash-specific constructs (`[[ ... ]]`, `((...))`) in shared candidate regions ([scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:47), [scripts/install.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.sh:292), [scripts/setup-project.sh](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.sh:88)). A “common.sh” is not portable to `sh` and may break if sourced from `zsh` context.
- PowerShell dot-sourcing risks: dot-sourcing imports into caller scope; function/variable collisions are likely because both scripts already define `Write-Ok/Write-Warn/Write-Info` and globals (`$ErrorActionPreference`, `$TARGET_*`, `$SETTINGS_FILE`) ([scripts/install.ps1](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.ps1:65), [scripts/setup-project.ps1](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.ps1:42), [scripts/install.ps1](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/install.ps1:32), [scripts/setup-project.ps1](/Users/matsumototoshihiko/Desktop/dev04/taisun_agent/scripts/setup-project.ps1:17)). Relative `. .\...` loading is also cwd-sensitive unless anchored to `$PSScriptRoot`.

## Counter-Proposal
- Extract first: only MCP merge/update behavior into a single existing entry point (`scripts/update-settings.js`) and call it from both setup scripts. This is the highest-confidence semantic duplication and avoids shell/PowerShell scope/path hazards.
- Extract second (PowerShell only): skills/agents sync into narrowly scoped functions with explicit parameters (`Source*`, `Target*`) and no shared global mutation. PowerShell has the denser real overlap.
- Defer: UI helpers (`ok/warn/info`, `Write-*`) and banner/echo text; `comm` overlap is mostly cosmetic and not worth new sourcing/dot-sourcing failure modes.
- Defer broad `setup-common.sh` until after smoke tests for both invocation patterns (`./scripts/...` and absolute path invocation from non-repo cwd) are in place.

## Confidence
High, because the stance is based on reproduced `comm` counts, direct inspection of both SH/PS1 common-line outputs, and concrete line-level comparison of the four scripts.
