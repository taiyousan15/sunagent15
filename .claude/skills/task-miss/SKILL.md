# Task-Miss Prevention Protocol

タスク実行時のミス防止プロトコル。900件+のリサーチ（2026-04-12）に基づく。
発動すると、このセッション内の全タスクに以下のプロトコルを適用する。

## 発動確認

このスキルが読み込まれたら、以下を1行で宣言せよ:
「Task-Miss Protocol ON — PreFlect・4Phase・CoVe・品質ゲートを適用します」

## Protocol

### 1. PreFlect（実行前批評 — 各タスク開始時に必須）

タスクに着手する前に、以下の3問に内部回答せよ（ユーザーに表示不要）:

```
Q1. このタスクで失敗しうる最大のリスクは何か？
Q2. 必要なファイルは全てReadしたか？（未読があれば先にRead）
Q3. 最適なエージェントは誰か？（該当があればAgent toolで委任）
```

3問の回答に基づき、計画を立ててから実行を開始する。

出典: arxiv 2602.07187 PreFlect — GAIAベンチマーク+17.14%改善

### 2. 禁止行動（違反はCRITICAL ERROR）

- 未読ファイルの内容を推測・捏造すること
- Readせずにファイルを編集・作成すること
- 「確認した」と言いながら実際に確認していないこと
- エージェント報告を目視検証せず転記すること
- 品質ゲート未通過でタスク完了を宣言すること
- 指示にない作業を無断で実行すること

### 3. 段階的実行フロー（Progressive Disclosure）

```
Phase 1: 調査 — 対象ファイルをRead、現状を把握
Phase 2: 計画 — 修正箇所と方法を明示（根拠はfile:lineで提示）
Phase 3: 実行 — 計画通りに修正（1ファイルずつ確認しながら）
Phase 4: 検証 — 品質ゲートを実行（全PASS後に次タスクへ）
```

各Phase完了後に次Phaseへ進む。Phaseをスキップしない。
ただし、明らかに単純なタスク（1ファイル1行修正等）はPhase 1+3+4に短縮可。

### 4. 品質ゲート（Phase 4で必須実行）

1. 変更したファイルをReadして目視確認（推測禁止）
2. 外部検証を実行（プロジェクトに応じて選択）:
   - TypeScript: `npx tsc --noEmit`
   - テスト: `npx jest`（期待値と照合）
   - Lint: `npx eslint`（0 problems必須）
3. 全検証PASS → 完了報告（証拠: file:line + テスト結果の数値）
4. 1つでもFAIL → 修正して再検証（最大2回。3回目はユーザーに報告）

### 5. CoVe: 完了報告前チェックリスト

完了を宣言する前に、以下を1つずつ確認:

```
□ 修正した全ファイルをReadで目視確認したか？
□ テスト結果の数値を実際のコマンド出力で確認したか？
□ 「全件一致」「問題なし」と言い切る前に自分の目で数えたか？
□ エージェント報告がある場合、元ファイルで突合したか？
```

1つでも未確認があれば、確認してから報告する。

出典: Chain-of-Verification — F1スコア+23%改善（Meta AI）

### 6. エラー回復

```
回復可能: テスト失敗、lint警告、型エラー → 修正して再検証（最大2回）
回復不能: 環境問題、権限不足、外部API障害 → 即座にユーザーに報告
  報告形式: 「[BLOCKED] 理由: {具体的な内容} / 試行した対処: {内容}」
```

### 7. エージェント選択

- タスク実行前に最適なエージェントを評価する
- 専門性が必要な場合はAgent toolで委任（subagent_type指定）
- 3つ以上の並列エージェント → run_in_background: true 必須
- エージェント結果は必ず自分で目視検証してから報告
