# Session End

セッション終了時に正確な指示書とログを作成するスキル。

## Phase 1: 数値検証

以下のコマンドを実行し、実測値を取得する。推測や記憶に頼らず必ず実行:

```bash
git log --oneline -5
git branch --show-current
git status --short | head -30
npx jest --no-coverage --forceExit --selectProjects unit regression workflow-phase3 integration 2>&1 | grep -E "^(Test Suites|Tests):"
npx eslint .claude/hooks/*.js --no-ignore --format compact 2>&1 | tail -1
```

## Phase 2: ログ作成

保存先: プロジェクト内「ログ/」フォルダに日付付きで保存
ファイル名: YYYY-MM-DD_セッションNログ.md

ログに含めるセクション:
1. セッション概要（日付、モデル、前セッション指示書パス）
2. 実施タスク一覧（各タスクの詳細、修正ファイル名:行番号）
3. 品質ゲート結果（テスト数、ESLint結果）
4. git状態（ブランチ、コミットハッシュ、未コミット変更）
5. 未完了タスク（次セッションへの引き継ぎ）
6. 重要な数値（全て実測値）

ルール:
- このセッションで自分が知っている事実だけを書く
- 推測で1文字も書かない
- 数値は全てPhase 1の実測値を使う

## Phase 3: 指示書作成

保存先: /Users/matsumototoshihiko/Desktop/指示書.md

指示書に含めるセクション:
1. 最初に読むべきファイル一覧（フルパス付き、順序指定）
2. 全セッション累計の完了事項（コミットハッシュ付き）
3. 未完了タスク（優先順、ファイル名、行番号付き）
4. 品質ゲートフロー
5. やってはいけないことリスト（mistakes.mdのPatternを反映）
6. 現在のgit状態（ブランチ、最新コミット、未コミット変更）
7. 重要な数値（全てPhase 1の実測値）
8. このファイルの使い方

ルール:
- 行番号はReadで確認済みのものだけ書く
- 完了タスクと未完了タスクを混同するな
- 前セッションの作業を今セッションの作業と混同するな

## Phase 4: 最終チェック

1. 指示書をReadして通読する
2. コミットハッシュがgit logと一致するか確認
3. 行番号が実ファイルと一致するか確認
4. 推測で書いた箇所が1箇所でもないか自問
5. 不正確なら修正

チェック結果を報告:

| チェック項目 | 結果 |
|------------|------|
| コミットハッシュ一致 | OK/NG |
| 行番号一致 | OK/NG |
| 推測箇所なし | OK/NG |
| テスト数値一致 | OK/NG |

全てOKの場合のみ「保存完了」と報告する。
